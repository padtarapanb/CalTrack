# CalTrack – ระบบสอบเทียบเครื่องมือวิทยาศาสตร์

หน้าเว็บสำหรับจัดการทะเบียนเครื่องมือ แผนสอบเทียบรายปีงบประมาณ (1 ต.ค. – 30 ก.ย.) คลังใบรับรอง และบันทึกผลสอบเทียบ
ใช้งานผ่านเบราว์เซอร์ ไม่ต้องมีเซิร์ฟเวอร์

## เมนูในระบบ
| เมนู | ทำอะไรได้ |
|---|---|
| แดชบอร์ด | สรุปจำนวนเครื่องมือ ใกล้ครบกำหนด เกินกำหนด และกราฟครบกำหนดรายเดือน |
| ทะเบียนเครื่องมือ | ค้นหา กรองกลุ่มงาน/สถานะ ขึ้นทะเบียนเครื่องมือ (รวมข้อมูลตามมาตรฐาน ISO) |
| แผนสอบเทียบ | สร้างแผนรายรอบ เลือกตามกลุ่มงาน ตัดเครื่องออกพร้อมเหตุผล ส่งออก CSV / พิมพ์ |
| บริษัท / ผู้รับผิดชอบ | ข้อมูลหลัก: บริษัทจำหน่าย, บริษัทสอบเทียบ (เลขที่รับรอง 17025), รายชื่อผู้รับผิดชอบ |
| ใบรับรองสอบเทียบ | จัดเก็บแยกตามปีงบประมาณ บันทึก U, เกณฑ์ยอมรับ, ผล และสถานะต่อไปเมื่อมีค่าแก้ |
| นำเข้า / สำรองข้อมูล | นำเข้าทะเบียนจาก Excel, ดาวน์โหลด/กู้คืนไฟล์สำรอง |
| แบบฟอร์มราชการ (บันทึก/ส่งออก) | เลือกแบบฟอร์มจากทะเบียนเอกสาร (รหัส/ชื่อ/Revision/วันที่อนุมัติ) แล้วกรอกฟอร์ม F 36 05 033 / F 36 05 040 / F 36 03 025 (รวมชื่อบริษัท ผู้รับผิดชอบ ผู้ประเมิน ผู้อนุมัติ) บันทึกเก็บไว้ และส่งออกเป็น PDF (พิมพ์) / Word ตามแบบฟอร์มหน่วยงาน — โค้ดอยู่ใน `forms.js` |
| บันทึกผลสอบเทียบ | กรอกจุดสอบเทียบ คำนวณ E, ค่าแก้ และตัดสิน ผ่าน / มีเงื่อนไข / ไม่ผ่าน แล้วส่งไปบันทึกเป็นใบรับรอง |

## หลักการจัดหมวดและสถานะ (ตั้งตามระบบคุณภาพของหน่วยงาน)
- **ประเภท**: เฉพาะ Lab / เครื่องมือรวม
- **หมวด** ตามผลกระทบต่อเกณฑ์ยอมรับ (ISO/IEC 17025, GMP/GLP): **A วิกฤต** กระทบผลโดยตรง ต้องมี U + เกณฑ์ + คีย์ค่าแก้ · **B สำคัญ** กระทบทางอ้อม ต้องมี U + เกณฑ์ คีย์ค่าแก้เมื่อ |E| เกินเกณฑ์ · **C ทั่วไป** แสดงผลเท่านั้น ไม่ต้องคีย์ค่าแก้ (ตัวอย่างเครื่องมือในแต่ละหมวดควรให้ผู้จัดการคุณภาพยืนยัน)
- **กฎตัดสิน**: |E| + U ≤ เกณฑ์ = ผ่าน · |E| ≤ เกณฑ์ แต่ |E| + U เกิน = ผ่านแบบมีเงื่อนไข · |E| เกินเกณฑ์ = ไม่ผ่าน
- **ผลมีเงื่อนไข/ไม่ผ่าน** ต้องเลือกสถานะต่อไป: ใช้งานต่อ (คีย์ค่าแก้) · ส่งซ่อม · ลดสถานะ · จำหน่าย · ตามระบบคุณภาพ (ต้องใส่เลข NCR/CAPA) — ระบบจะเปลี่ยน “การใช้งาน” ของเครื่องและ **ไม่เลื่อนรอบครบกำหนด** ถ้าไม่ได้ใช้งานต่อ

## เริ่มใช้งานกับข้อมูลจริง
1. เปิดเว็บ → เมนู **นำเข้า / สำรองข้อมูล** → เลือกไฟล์ Excel
2. เลือกชีตที่ต้องการ (ปกติเลือกชีตแยกกลุ่มงาน ส่วนชีต “รวม” ใช้เติมข้อมูลที่ขาด) ตรวจ “รายการที่ควรตรวจสอบ”
3. กด **นำเข้าข้อมูล** (ติ๊ก “ล้างข้อมูลตัวอย่าง” ครั้งแรก)

ระบบแปลงวันที่ให้อัตโนมัติ (ข้อความไทย, ปี พ.ศ./ค.ศ., ปีที่พิมพ์ผิด) รวมแถวซ้ำตามรหัสครุภัณฑ์ และข้ามชีตแบบประเมินผลที่มีคอลัมน์ “ค่าที่วัดได้”
เครื่องที่หมายเหตุมีคำว่า “จำหน่าย” จะแสดงสถานะ “จำหน่ายแล้ว” และไม่นับเป็นเกินกำหนด

## ข้อมูลเก็บที่ไหน (สำคัญ)
- ข้อมูลเก็บใน **เบราว์เซอร์ของเครื่องที่ใช้งาน** เท่านั้น (localStorage) ไม่ส่งขึ้นอินเทอร์เน็ต
- เปิดคนละเครื่อง/คนละเบราว์เซอร์จะไม่เห็นข้อมูลเดียวกัน และถ้าล้างข้อมูลเบราว์เซอร์ข้อมูลจะหาย
- ให้กด **ดาวน์โหลดไฟล์สำรอง (.json)** เป็นประจำ แล้วเก็บไว้ในที่ปลอดภัย
- **ไฟล์ใบรับรอง (PDF/รูป) ยังไม่ถูกเก็บถาวร** ระบบเก็บเฉพาะชื่อไฟล์
- ยังไม่มีระบบล็อกอินและสิทธิ์ผู้ใช้ จึงเหมาะกับ 1 คนที่ดูแลทะเบียน หรือใช้ทดลองก่อน

ถ้าต้องการใช้หลายคนพร้อมกัน เก็บไฟล์ใบรับรองจริง และมีประวัติแก้ไข (audit trail) ตามมาตรฐาน ต้องต่อฐานข้อมูลและที่เก็บไฟล์เพิ่ม (เช่น Supabase)

## ไฟล์ในโปรเจกต์
| ไฟล์ | คืออะไร |
|---|---|
| `index.html` | ระบบหลัก |
| `forms.js` | โมดูลแบบฟอร์มราชการ (บันทึก + ส่งออก PDF/Word) |
| `line.html` | ต้นแบบหน้าจอแจ้งเตือน LINE (ยังไม่เชื่อมจริง รอ token) |
| `config.js` | ใส่ URL ของ Google Apps Script (เชื่อมระบบกับ Google) |
| `Code.gs` | โค้ดฝั่งเซิร์ฟเวอร์สำหรับ Google Apps Script (ไม่ได้รันบน Vercel) |
| `vercel.json` | ตั้งค่าให้ Vercel เปิดเว็บจากโฟลเดอร์หลัก และโหลดฟังก์ชัน |
| `api/` | `line-webhook` (ตอบ Group ID), `notify` (แจ้งเตือนทุกวัน), `line-test` (ทดสอบ) |

## นำขึ้น GitHub และเปิดเว็บบน Vercel (ทำครั้งเดียว)
**A. GitHub:** สมัคร https://github.com → **New** → ตั้งชื่อ repository (เลือก **Private**) → **uploading an existing file** → ลากไฟล์และโฟลเดอร์ `netlify` ทั้งหมด → **Commit changes**

**B. Vercel:** สมัคร https://app.netlify.com ด้วย **Sign up with GitHub** → **Add New… → Project → Import Git Repository** → เลือก repository → Build command ว่าง, Framework Preset: **Other**, Root Directory `./`, Build Command ว่าง → **Deploy** ได้ลิงก์ `xxxx.netlify.app`

**C. แก้ไขภายหลัง:** เปิดไฟล์ใน GitHub → ไอคอนดินสอ → แก้ → **Commit changes** แล้ว Vercel อัปเดตเอง

## ข้อควรระวัง
- repository ควรเป็น **Private** และห้ามใส่ข้อมูลจริง ไฟล์ Excel ทะเบียน หรือ LINE token ลงใน GitHub
- ไฟล์ Excel ใช้นำเข้าผ่านหน้าเว็บบนเครื่องของคุณเท่านั้น ไม่ต้องอัปโหลดขึ้น GitHub
- ถ้าเว็บเปิดบน Vercel แบบสาธารณะ ใครมีลิงก์ก็เปิดหน้าเว็บได้ แต่จะไม่เห็นข้อมูลของคุณ เพราะข้อมูลอยู่ในเครื่องคุณ

## เชื่อม Google Drive / Sheets (ผู้ชม–ผู้ดูแล, เก็บไฟล์ใบรับรอง)
ทำให้ได้: ข้อมูลอยู่ที่ Google ใช้ร่วมกันหลายเครื่อง, ไฟล์ใบรับรองถูกสร้างโฟลเดอร์ `CalTrack-ใบรับรอง / ปีงบประมาณ XXXX / กลุ่มงาน` อัตโนมัติ,
ผู้ชมดูและดาวน์โหลด PDF ได้อย่างเดียว, ผู้ดูแลเท่านั้นที่แก้ไขได้ (ตรวจที่เซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนปุ่ม)

1. เข้า https://script.google.com ด้วยบัญชี Google ของหน่วยงาน → **โครงการใหม่** → ลบโค้ดเดิม แล้ววางเนื้อหา `Code.gs` ทั้งไฟล์ → บันทึก
2. **Project Settings (ไอคอนเฟือง) → Script properties → Add property**
   ชื่อ `ADMIN_USERS` ค่า `{"สมหญิง":"รหัสผ่านที่ตั้งเอง","สมชาย":"รหัสผ่านอีกอัน"}` (ตั้งรหัสผ่านที่เดายาก)
3. **Deploy → New deployment → ประเภท Web app** → Execute as: **Me** / Who has access: **Anyone** → Deploy → กด Authorize อนุญาตสิทธิ์ Drive/Sheets → คัดลอก **Web app URL**
4. เปิดไฟล์ `config.js` ใน GitHub (ไอคอนดินสอ) วาง URL ระหว่างเครื่องหมายคำพูด → Commit changes → Vercel อัปเดตเอง
5. เปิดเว็บ: ทุกคนเห็นแบบ “ผู้ชม” ผู้ดูแลกด **เข้าสู่ระบบผู้ดูแล** (มุมซ้ายล่าง) แล้วกรอกชื่อ+รหัสผ่านจากข้อ 2
6. ครั้งแรกให้ผู้ดูแลเข้าสู่ระบบ → เมนู นำเข้า/สำรองข้อมูล → นำเข้า Excel (หรือกด “ซิงก์ขึ้น Google ตอนนี้”)

**ข้อควรรู้**
- ถ้าแก้ `Code.gs` ภายหลัง ต้อง Deploy → Manage deployments → Edit → New version จึงมีผล
- “Anyone” หมายถึงใครมี URL ก็อ่านข้อมูลทะเบียนได้ (ชื่อเครื่อง ผู้รับผิดชอบ ลิงก์ไฟล์) แต่เขียนไม่ได้ ถ้าข้อมูลสำคัญกว่านี้ให้ปรึกษาฝ่ายไอที
- ไฟล์ใบรับรองถูกตั้งเป็น “ใครมีลิงก์ดูได้” เพื่อให้ผู้ชมดาวน์โหลดได้ ใครได้รับลิงก์ก็เปิดได้
- ถ้าผู้ดูแล 2 คนแก้พร้อมกัน ระบบจะแจ้ง “ข้อมูลขัดแย้ง” ให้โหลดข้อมูลล่าสุดก่อน
- บันทึกการแก้ไข (ใคร/เมื่อไร/ก่อน-หลัง) เก็บในระบบและสำเนาในชีต `บันทึกการแก้ไข` ชื่อผู้ทำรายการมาจากบัญชีที่ล็อกอินจริง
- ข้อมูลสำหรับ ISO 15189 ที่เกี่ยวกับผู้ป่วย ไม่ควรเก็บในระบบนี้

## เชื่อม LINE (มี OA และเชิญบอตเข้ากลุ่มแล้ว แต่ยังไม่มี Group ID)
ดูขั้นตอนพร้อมรูปแบบการตั้งค่าที่หน้า `line.html` แท็บ “ขอ Group ID” สรุป: ตั้ง env `LINE_CHANNEL_SECRET` + `LINE_CHANNEL_ACCESS_TOKEN` → deploy → ใส่ Webhook URL `/api/line-webhook` ใน LINE Developers แล้วเปิด Use webhook → พิมพ์ `groupid` ในกลุ่ม บอตตอบ Group ID → ใส่เป็น `LINE_GROUP_ID` พร้อม `CALTRACK_API`, `TEST_KEY` → ทดสอบที่ `/api/line-test?key=...`

**หลังอัปเดตครั้งนี้ต้อง Deploy → Manage deployments → Edit → New version ใน Apps Script ใหม่** เพื่อให้ Code.gs เก็บคอลัมน์/ชีตใหม่ (ประเภท, หมวด, บริษัท, U, ค่าแก้ ฯลฯ)


## ข้อมูลเก็บที่ไหน / ดูและดาวน์โหลดอย่างไร
- **โหมดเครื่องเดียว** (ยังไม่ใส่ URL ใน `config.js`): ไม่มีไฟล์ฐานข้อมูล ข้อมูลอยู่ในเบราว์เซอร์ของเครื่องนั้น (localStorage คีย์ `caltrack-v1`) เปลี่ยนเครื่อง/ล้างประวัติ ข้อมูลหาย → ไปที่เมนู **นำเข้า / สำรองข้อมูล → ดาวน์โหลดไฟล์สำรอง (.json)** เป็นระยะ
- **โหมด Google** (ใส่ URL Apps Script ใน `config.js`): ข้อมูลอยู่ใน Google Drive ของบัญชีที่ deploy Code.gs โฟลเดอร์ CalTrack มีไฟล์ `caltrack-data.json` (ข้อมูลหลัก) และชีต **CalTrack-ทะเบียน** (ดู/ดาวน์โหลดเป็น Excel ได้ที่ Drive → คลิกขวา → ดาวน์โหลด)
- **Vercel ไม่เก็บข้อมูล** ทำหน้าที่เสิร์ฟหน้าเว็บและส่ง LINE เท่านั้น
